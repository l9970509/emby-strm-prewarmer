# Emby 媒体信息预热工具（飞牛 OS 原生）

为 Emby 中的 **STRM 媒体**提前获取真实 MediaInfo，消除首次播放前 ffprobe 探测导致的长时间转圈。

原理与 [emby-strm-prewarmer](https://github.com/ado-uta/emby-strm-prewarmer) 一致：通过 Emby API 主动调用
`PlaybackInfo`，让 Emby 真正读一次网盘 / 302 直链媒体文件，把分辨率、编码、码率、音轨等**真实**信息
写进 Emby 自己的媒体库数据库。

- ✅ 不下载完整视频，不修改 STRM / NFO，不注入虚假媒体信息
- ✅ 自动跳过已预热影片，只做增量；同名 STRM 换源自动识别（内容指纹按**链接语义**比较）
- ✅ 预热完成后导出 `{filename}-mediainfo.json` 备份（StrmTool 兼容格式，可反向恢复）
- ✅ 备份可同步到独立备份目录（对比增量、结构一致、可选图片字幕）
- ✅ PushPlus / Webhook 完成通知，只在有实际变动时推送
- ✅ 纯 Python 标准库，零第三方依赖；提供飞牛 fpk 原生安装包（统一网关，桌面内打开面板）

## 功能一览

| 功能 | 说明 |
| --- | --- |
| 一键预热 | 面板按钮 / `python3 run.py once`，全量增量预热 |
| 定时预热 | 固定间隔，或每天多个时刻（如 03:30、12:00、22:00） |
| 新片入库监听 | 按入库时间增量查询 Emby，发现新片立即预热 |
| 入库通知唤醒 | 接收 Emby Webhooks 的 `library.new`，秒级响应 |
| 失败循环预热 | 单项重试 + 运行内多轮 + 后台指数退避持续重试 + 手动预热 |
| 媒体信息备份 | 自动导出 mediainfo.json，另有全库补导出模式 |
| 备份同步 | 同步到备份目录 B，B 已存在跳过、不存在复制；手动/预热后/定时触发 |
| Web 面板 | 四页面（预热 / STRM 生成 / 备份同步 / 任务记录）、日志窗口固定高度内部滚动、失败队列、在线改配置 |
| 消息通知 | PushPlus（微信）与通用 Webhook，附发送测试按钮 |

## 快速开始

> **下载最新安装包**：[Releases · v1.9.6](https://github.com/l9970509/emby-strm-prewarmer/releases/latest)

### 飞牛 OS（推荐）

应用中心「手动安装」选择 `embyprewarm-1.9.6.fpk`，或在 SSH 中：

```bash
sudo appcenter-cli install-fpk embyprewarm-1.9.6.fpk
```

装完点桌面图标即可在飞牛 Web 桌面内打开面板（路径 `/app/embyprewarm`）。
记得在「应用中心 → 设置 → 授权目录」添加影视目录读写权限，否则备份无法写入。

### 其他 Linux（systemd）

```bash
cd emby-prewarmer
sudo bash install.sh              # 默认 /opt/emby-prewarmer，端口 8787
```

浏览器打开 `http://NAS的IP:8787`，右上角齿轮填写 Emby 地址 / API Token / 媒体根目录 / 路径映射。

详细配置说明见 [emby-prewarmer/README.md](emby-prewarmer/README.md)。

## STRM 生成与全自动闭环

面板第四个页面「STRM 生成」可以把 OpenList（AList 兼容）网盘目录同步成本地 `.strm`：

1. 填 OpenList 地址 + 长期令牌（或账号密码）、STRM 前缀（`http://IP:5244/d` 或 rclone 挂载根），
   点「测试 OpenList 连接」确认可用

   > 前缀只填 `IP:5244/d` 会自动补成 `http://IP:5244/d`；**留空则用 OpenList 地址 + `/d`**。
   > 实际写入内容 = 前缀 + 网盘完整路径，例如
   > `http://192.168.101.99:5244/d/2dland/%E7%94%B5%E8%A7%86%E5%89%A7/.../爱情公寓%20-%20S01E01%20-%202dland.mp4`
2. 点「添加目录」添加生成任务：网盘目录可以直接**从 OpenList 目录树里浏览选择**；「本地根目录」
   填镜像根，strm 会落在 `根目录 + 网盘完整路径` 下（例如网盘 `/2dland/动画`、根 `/vol2/…/strm`，
   实际输出 `/vol2/…/strm/2dland/动画/…`），目录结构与网盘完全一致，多个任务可共用同一个根
3. 每个任务可单独：启用/停用、设置**每天多个定时时刻**、选择默认「增量」或「全量」模式、
   是否清理网盘已删除的 strm
4. 每个任务卡片上有「增量生成」「全量生成」按钮，点开后先看明细预览（新增/更新/跳过/删除），
   确认后才写盘；顶部「全部生成」按各任务自己的模式一起跑

两种模式的区别（都只作用于该任务自己的目录）：

| 模式 | 对比方式 | 适合场景 |
| --- | --- | --- |
| 增量 | 逐个对比网盘文件与本地镜像目录：本地没有的生成（新增）；已有的会**校验 strm 里的链接**，一致就跳过，不一致（换过前缀/换过源）才更新。BOM、CRLF、编码大小写（%e7/%E7）、%20 与 +、中文是否编码这些等价写法不算差异 | 日常定时跑，只补新片、自动纠正旧链接 |
| 全量 | 不看本地是否已存在，整目录重写一遍 | 大批量改前缀、需要彻底重建 |

> 附件（nfo/字幕/海报）在任何模式下都只补缺失文件，不重复下载。
> 从旧版本升级：本地目录含义变为「镜像根」，首次运行会把旧布局（直接落在根目录下的 strm）
> 自动搬移到 `根目录/网盘完整路径` 的新结构里，日志里会显示「迁移」数量。

执行时「生成」页的日志会逐条列出每个文件做了什么，每个任务独立成段：

```
📼 开始生成 STRM（手动生成）：2 个任务 · 强制增量模式 · 前缀 http://192.168.101.99:5244/d
　└─ [增量] 电影：/2dland/电影 → /vol2/1000/影视库/Ostrm/strm/2dland/电影
　　扫描 42 个远端文件：新增 2 / 更新 0 / 跳过 40 / 迁移 0 / 删除 0 / 附件 1
　　✓ 新增 2dland/电影/沙丘 (2024)/沙丘 (2024).strm
　　⤓ 附件 2dland/电影/沙丘 (2024)/poster.jpg
　└─ 电影 完成（0.6 秒）：新增 2 / 更新 0 / 跳过 40
　└─ [增量] 剧集：/2dland/剧集 → /vol2/1000/影视库/Ostrm/strm/2dland/剧集
　　扫描 5 个远端文件：新增 0 / 更新 0 / 跳过 5 / 迁移 0 / 删除 0 / 附件 0
　　✓ 全部已是最新，本次没有需要写入的文件
　└─ 剧集 完成（0.1 秒）：新增 0 / 更新 0 / 跳过 5
```

- 每个任务都有自己的明细额度（手动 2000 条 / 定时 300 条），前面的任务不会把后面的额度用光
- 明细超限时会明确写出「另有 N 条未逐条显示」，不会静默省略
- 全部跳过时也会输出扫描结果与「全部已是最新」，不会再出现"点了没反应"的错觉

生成后**不主动预热**——等 Emby 扫描到新 strm 并发出入库通知（Webhooks `library.new`），
本工具收到通知再触发增量预热，形成闭环：

```
网盘更新 → 生成 STRM → Emby 入库通知 → 自动增量预热 → 导出 mediainfo.json → 自动同步备份目录 B
```

全链路都在本工具内完成，每一步都有独立日志页面与变动通知（只推有实际变动的任务）。

### 新片没有自动预热？按这个顺序查

生成 strm 之后本工具**不会自己去预热**，必须由「入库通知」或「新片监听」来触发。所以排查顺序是：

1. **入库通知开着吗** — 设置 →「入库通知（Webhook 唤醒）」开关。关着的话，Emby 就算发了通知也会被忽略，
   日志（预热页）现在会明确写出「收到通知但开关是关闭的」。
2. **Emby 端的 Webhook 地址对吗** — Emby 控制台 → 插件 → Webhooks → 添加通用 Webhook：
   `http://NAS的IP:8799/hook/emby?api_key=你在设置里填的令牌`，事件勾选「新媒体已添加」。
   地址里的 `api_key` 与设置里的令牌不一致会被拒绝，预热日志会写「api_key 校验失败」。
   > fpk 应用包默认用 **8799**（只给 Webhook 用，面板走飞牛统一网关）；脚本安装默认 **8787**。
   > 以「设置 → 面板端口」显示的值为准，端口填错时 Emby 侧会直接连接失败。
3. **打开新片监听兜底** — 设置 →「新片监听」开启后按 `poll_seconds` 轮询 Emby 的入库时间，
   即使 Webhook 没配好也能自动预热（默认 300 秒）。
4. **Emby API Token 是不是被打码值写坏了** — 老版本曾把 `********abcd` 这种展示值存回配置，
   升级后设置页会显示红色提示条，重新填一次 API 密钥即可。
5. **路径映射** — 预热日志里出现「有 N 个 STRM 无法读取本地文件…建议检查路径映射」，
   说明 Emby 里的路径和 NAS 上的实际路径对不上（只影响换源指纹，不影响预热本身）。

预热本身的所有动作都在「预热」页日志里：扫描统计、逐条成功或失败、失败原因与失败队列。
扫描完成那一行是四个数字：

```
扫描完成：STRM 15677 个 / 已完整 15598 个 / 待预热 79 个 / 内容有更新 0 个 / 失败队列 0 个
```

- **待预热**：Emby 里还没有完整 MediaInfo 的条目，必须探测
- **内容有更新**：已完整，但 strm 指向的地址变了（换源/换前缀），需要重新探测
- **本次预热数量 = 待预热 + 内容有更新**；两项都是 0 时日志会直接说「已是最新状态」
- 指纹按**链接语义**计算：BOM、Windows 换行、`%E7`/`%e7`、`%20` 与 `+`、中文是否编码都视为
  同一个链接，增量生成顺手规范化格式不会引来整库重新预热

面板的日志窗口是**固定高度**（桌面 340px、窄屏 260px），内容在窗口内部滚动，页面长度不会随日志增长。

## 自行打包 fpk

```bash
python3 tools/build_fpk.py        # 输出 embyprewarm-<manifest 版本号>.fpk
```

修改源码后需同步到 `fpk/embyprewarm/app/prewarmer/` 再打包（打包脚本读取该目录）。
